# Reviewed-source build broker

The supervisor's `--build-command` invokes an immutable installed wrapper for:

```sh
exec /path/to/pinned/sim-latency source-build-broker \
  --build-settings=/path/to/private/build-settings.json \
  --build-settings-sha256=<sha256-of-those-exact-settings-bytes>
```

Render and pin the wrapper before deployment; placeholders are not runnable
configuration. The broker requires root for its fixed local Docker socket.
The pinned wrapper must select the executable and settings, not candidate input.
The parent pins the rendered wrapper using `--build-sha256`.

The settings file must be a private regular file at its canonical absolute path.
Create the state directory mode 0700. Example settings shape:

```json
{
  "sandbox": {
    "state_directory": "/var/lib/urnetwork/competition-reviewed-builds"
  },
  "qualification_command": "/path/to/independently-qualified/qualifier",
  "qualification_sha256": "<exact-qualifier-sha256>"
}
```

Omitted limits use the defaults in `source_build_sandbox.go` and
`source_build_broker.go`. Byte/count limits are positive; durations use Go's
JSON numeric nanoseconds and must be positive. The default total deadline is
three hours. The qualifier must exist, be non-writable by group/other, and
match its digest before expensive work begins; it is checked again at launch.
Settings contain no main or model credentials.

The JSON request on stdin is generated by `stage-reviewed-source`, after a
genuine API approval. It binds the patch, prospective generation, all ten
repository commits and the immutable incumbent image. The broker:

1. Fetches only each exact approved commit into a private checkout. It excludes
   ignored files, shared Git object links, private origins and transport paths.
2. Exports bounded module metadata from the incumbent, rejecting archive path
   traversal, links, special files, duplicate entries and excess bytes/counts.
3. Runs offline checking and compilation in separate constrained containers,
   with read-only host mounts and independent temporary cache seeds.
4. Authenticates the compiled binary's module, package, clean Git revision,
   Linux/amd64 executable target and disabled cgo.
5. Assembles a copy-only image with no candidate Dockerfile commands, checks
   the actual base identity, rejects inherited `ONBUILD` hooks and binds the
   resulting image to this build owner.
6. Calls the pinned independent qualifier with operation
   `qualify_exact_reviewed_source_image`, the original build request, owner,
   exact image ID, binary digest and private artifact directory.

The qualifier must actually run the independent Sol 6.1 low tests and obtain
image-bound containment/host evidence. It returns the strict
`reviewedSourceBuildReceipt` JSON contract. The broker checks all original
review/patch/source identities, actual image ID and `sandbox_id == owner`.
It cannot manufacture model provenance from a Go exit status or a hash string.
Only a complete passing receipt is persisted and returned on stdout.

No API/MinIO/main credentials or config/vault trees are mounted during the
offline build phases. Later runtime qualification may use only direct
`config/local` and `vault/local` read-only leaves, never their parents or `all`.
All phase failures stop progression and retain private bounded diagnostics.
Temporary source contexts/images remain evidence until authenticated retention
permits cleanup. Nothing here pushes source refs or activates a round.

## Release status

The broker entry point and interlocks require deployment qualification. A real
independent qualifier is still required; this repository does not install or
assert one by supplying an executable pathname. Do not enable production with
a stub qualifier or use synthetic test receipts as operational evidence.

The independent test-model client in `source_test_model.go` uses Sol 6.1 low
with one forced, argument-free `run_prescribed_tests` tool. Its trusted callback
owns the fixed suite; the model cannot choose commands or grant approval. A
second, tool-disabled response must agree with the observed exit status and
nonzero test count. Evidence binds the exact image, suite, logs and both actual
provider response IDs, and records usage. Model commentary cannot substitute
for execution. Short provider deadlines do not shorten the separate test
budget or extend an earlier parent deadline.

This client has mocked transport/authority regression coverage, not live model
qualification. The installed qualifier must still integrate the real fixed-suite
executor, durable plan/response/execution journal, host/containment evidence and
artifact retention. Do not retry a completed failed/uncertain test or model
outcome until operator investigation; only an incomplete transport may resume
the same original plan without rerunning completed tests.

The implementation follows the official [function-calling contract](https://developers.openai.com/api/docs/guides/function-calling)
and [stateless reasoning-item replay](https://developers.openai.com/api/docs/guides/reasoning).
Opaque encrypted reasoning items are forwarded for continuation, never decoded
or exposed as an audit explanation. No main/model credential enters model input.

The fixed offline executor in `source_test_suite.go` now covers 33 mandatory
named tests across server error classification, the permitted resident-contract
manager/cache/read/lease/fallback surface, and protected simulator/scoring
behavior. It runs the prescribed selectors in a separate offline container,
using a fresh metadata seed and read-only source. Complete Go test events must
prove every mandatory test ran and passed and every package completed. Logs are
retained before their exact digest is returned. This is a targeted correctness
suite, not the complete repository/database suite or live smoke/host proof.
The full real-container synthetic probe passed all 33 tests with owned-image
and container cleanup. Direct shell-run probes do not constitute model-owned
execution or a complete live qualification receipt.

`executeJournaledSourceCorrectness` durably reserves the exact image/owner/patch/
source/suite plan before container execution. It atomically publishes completed
observations and revalidates their retained log bytes on replay. Completed
failures remain failures; a changed plan, corrupt record, missing evidence, or
unfinished reservation cannot start another execution. A pending reservation
means active **or** interrupted, not proof its process stopped. Reconcile the
actual owner rather than deleting the journal to force another test draw.
The real qualifier still needs provider-response journaling and full deployment
integration; this execution journal alone is not a model or host receipt.
