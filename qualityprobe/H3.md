# HTTP/3 (UDP) in the provider quality probe

Owner request, 2026-11-11: "some providers do not route udp traffic. ... tests
https and h3 for each provider where the url support both https and h3. A
provider should pass the quality probe only if both tcp and udp pass. For urls
without an h3 support, only https is used for pass."

The URL list is `config/main/qualityprobe.yml` (config b2e0b76 marks 80 of its
173 URLs `h3: true` and adds 97 h3 candidates; the research is factury
`reports/Quality probe HTTP3 support.md`). `config/all/egress-sites.yml` is no
longer read by any server code (every reader uses the resource name
`qualityprobe.yml`, `model.ProviderEgressSitesResourceName`).

## Where the probe runs and what reads it

- **Scheduling and measuring.** The taskworker's URL lane
  (`taskworker/work/provider_url_probe_work.go`) claims due providers, opens one
  provider tunnel per turn (`qualityprobe/fleetprobe`, `providertunnel.Open`: a
  gVisor tun whose packets go through a `RemoteUserNatMultiClient` pinned to the
  provider), and fetches one random catalog URL (`egresshealth.Check` with
  `UrlProbe`, `url_fetch.go`). The standalone `cmd/egress-prober` runs the same
  workflow against the API over HTTP.
- **Ingest and storage.** The taskworker's in-process operator
  (`localoperator`) calls `controller.SubmitProviderEgressHealth`, which stores
  each outcome in `provider_egress_health_history` (ok_count/total_count,
  `url_probe_evidence` JSONB) and the latest-run row `provider_egress_health`.
  The 8-hour window over the history (`providerEgressHealthWindowSql`) is what
  everything reads.
- **Who reads it.** The bucket rule (`model/egress_index.go`
  `decideProviderEgress`): Quality and Speed native membership needs a URL ratio
  of at least 4/5 (`ComputeEgressIndex`) and minimum runs; the Online rule
  (`egress_online_success.go`) removes a provider with at least two general runs
  and no success in 8 hours (`no_success`); the rollup index sets the Quality
  tier; the score export weights draws by URL success (`network_client_score_rank.go`);
  FindProviders2 pools, location counts and the location list
  (`network_client_location_model.go`); provider status shown in the apps
  (`provider_status_model.go`); zero-carry (`provider_zero_carry.go`); TLS
  findings (`provider_egress_tls_verdict.go`). One failed outcome lowers a
  provider's rank; reliability is unaffected.
- **Connected status.** The apps decide Connected by provider counts
  (sdk `gridConnectionStatus`). URL outcomes reach it only through removals
  (`no_success`, zero-carry, a TLS finding judged the provider's) and the
  location's `ProviderCount`; a failing ratio keeps the provider in the Online
  fallback.
- **SN25.** SN25 scoring, weights and payouts read none of this: the
  validator's trail hops, stats and weights (`sn/validator`, `model/verify_*`),
  and the payout share (UsageBytes from contract usage, Wilson reliability,
  `controller/st_controller.go`) have no reference to URL outcomes. The links
  are indirect: the validator's seed picker asks FindProviders2's Online pool
  (seeds are excluded from its statistics), and a provider routed less carries
  less traffic, so earns less in SN25 and ordinary payouts alike. That is the
  same kind of change as the modern-provider gate, which is on the /mainnet
  timeline; a draft entry is on web branch `docs/mainnet-quality-probe-h3`.

## Design

**The flag.** `h3: true` on a destination, candidate or country entry
(`controller.ParseProviderEgressSites`); a missing key is false. It is served
with the pool (`egresshealth.Destination.H3`, JSON `h3`, omitted when false, so
the pool version changes only for URLs that declare it). The pool table keeps
no copy: config owns URL contracts (`configuredRows`), so no column is needed.

**The legs.** A URL turn of an h3 destination makes its HTTPS leg as before
and, only if that passed, the same request over HTTP/3 through the same
provider (`egresshealth/url_h3.go`): the same destination, request profile,
redirect policy (every hop over HTTP/3) and contract, judged by the same
`fetchUrlProbe`. The leg dials UDP to the URL's own host and port directly
(no Alt-Svc discovery): `providertunnel/http3.go` opens a connected UDP socket
of the tunnel's own gVisor stack (`Tun.DialContext("udp4", ip:port)`), never a
host socket, after admitting the host exactly as the HTTPS leg does
(`admitTls`: the closed allowlist and the request's exact redirect grant) and
resolving it through the tunnel's own resolver (`providerUrlResolver.resolve`,
public IPv4 only for a URL probe). TLS is WebPKI plus the same pins. quic-go
`http3.Transport` (already a server dependency, v0.61) runs over it with one
QUIC v1 connection per request, no 0-RTT, no session reuse, and datagrams of at
most 1252 bytes with path MTU discovery off, so every packet fits the probe
tunnel's 1280-byte IPv4 link. No connect or sdk change is needed: a real local
provider carries the leg end to end (`TestH3LegThroughALocalProvider`).

**Timeouts.** The leg gets the ordinary per-request timeout (10 s; the tunnel
is warm). The QUIC handshake idle bound is the HTTPS leg's TCP connect bound
(3 s), so a provider that drops UDP fails at 3 s; quic-go also aborts a
handshake that has not completed in twice that (the HTTPS connect and TLS
bounds together). After the handshake, the read-idle bound is the HTTPS leg's
(5 s). There is no retry: URL turns have one attempt and the server paces the
next turn, as for HTTPS. The run budget counts one more per-request timeout
per URL attempt (`Options.RunBudget`), so the turn reserve is 230 s (was 220 s)
and the publication reserve 320 s, within the 6-minute renewal headroom (40 s
margin, was 50 s). With a dual-stack provider's IPv6 legs (IPFAMILY.md) the
reserve is 250 s and the publication reserve 340 s (20 s margin).

**What the HTTP/3 leg proves** (`egresshealth.UrlProbeH3Udp`, evidence `h3.udp`):

| udp | what happened | the load |
|---|---|---|
| passed | the leg met the URL contract | passes (with its HTTPS leg) |
| answered | the site answered over QUIC and refused or failed the request: a TLS alert (0x128 handshake_failure from Cloudflare/CloudFront without h3, 0x150 from Akamai, 0x146, 0x178), a reset, a Retry then a stall, a certificate, or a response that failed the contract | passes: the provider carries UDP to the site; what the site does with HTTP/3 is not the provider's |
| silent | not one datagram came back to the QUIC Initial before the handshake bound or the request deadline ended it (`dial_quic`; the tunnel socket counts the datagrams it receives) | fails at `failure_stage: h3`, then judged by place |
| not_measured | the leg never sent UDP (local socket, policy, DNS), or the tunnel's loss or the run's end cut it short (`request_canceled`) | not measured, as for HTTPS |

**Judged by place, like TLS findings** (`model/provider_egress_h3_place.go`).
UDP is not neutral by place: Russia, China and Iran are reported to block or
throttle QUIC, and enterprise networks drop UDP 443. Where a national firewall
makes UDP results say nothing about the provider, the catalog turns the UDP
legs off for the country (the per-country switch below). Elsewhere a silent
leg counts against its provider only where the place carries QUIC to that URL:

- Place evidence is per URL, country and UTC day (`provider_egress_h3_place`):
  the established networks (at least 14 days old, the TLS place rule's age)
  whose exits in that country reached the URL over QUIC (passed or answered).
  A day keeps at most 8 networks, so it costs at most 8 writes a day per URL
  and country; every other leg that reaches its site costs two indexed reads
  (its provider's place and network, and the day's row) and takes no row lock.
- The ingest judges each silent leg as it arrives (`JudgeProviderEgressH3`,
  called by `controller.SubmitProviderEgressHealth` before the store):
  **provider** when at least 3 networks other than the provider's own reached
  the same URL over QUIC from the same country that day or the day before (the
  outcome fails); **place** otherwise (the outcome counts as its HTTPS leg,
  which passed, exactly as for a URL without h3: ok, class tally, rolling quota
  and pacing all follow). The verdict is kept in `url_probe_evidence.h3.verdict`
  and counted in `urnetwork_egress_url_h3_verdicts_total{verdict}`. A prober
  that sends a verdict is refused.
- Counted by network, a farm on one network cannot make the place for its
  neighbours; young networks make none; the provider's own network never
  counts; an unknown country is judged the place's.
- A URL whose HTTP/3 stops working everywhere stops producing place evidence,
  so its silent legs become place verdicts within two days; until then they
  count where yesterday's evidence stands.

**Kept apart.** The HTTPS leg's record is unchanged in the evidence; the leg is
`url_probe_evidence.h3`. Site tallies (the refresh's retirement, the TLS judge's
"country works" share) and the D3/D4 country-site pair tally judge sites by the
HTTPS leg (`CheckResult.HttpsOk`, `UrlProbeEvidence.HttpsOk`), so a site never
moves toward retirement because providers do not carry UDP; so does the
refresh's prober-fault line (`GetProviderEgressHealthContactedTotal`: the
refresh stops while over 20% of the last hour's contacted loads fail, 2.3% on
Main at 12:30Z on 2026-11-11), so a fleet short of UDP cannot stop it. TLS findings stay
about the HTTPS identity: a certificate failure over QUIC is recorded in the
leg (`tls_failure`) and is not URL security evidence. Security rechecks make no
HTTP/3 leg.

**Metrics.** `urnetwork_url_probe_transport_outcomes_total{transport="tcp|udp",outcome}`
(taskworker; udp outcomes success, answered, silent, not_measured, skipped; a
`family` label and more outcomes come with IPFAMILY.md);
`urnetwork_egress_url_h3_verdicts_total{verdict="provider|place"}` (ingest);
`urnetwork_url_probe_h3_common_mode_held_total`. The existing series keep their
names and meaning (`urnetwork_url_probe_outcomes_total` counts the prober's
verdict, `urnetwork_egress_url_outcomes_total` the stored one). Dashboard:
"urnetwork / provider quality probes", row "URL legs by transport". The probe
log line gains `h3=` (ok, silent, skipped, not_measured or the answered leg's
stage), and `failure_stages=` can count `h3`; the monitor's record pattern
(`monitor/tailer.go`) knows both, so the records stay out of its novel class.
`urnetwork_url_probe_udp_country_disabled_total{country}` (taskworker) counts
the loads whose HTTP/3 legs the per-country switch turned off, by the claim's
country; such a load counts `country_disabled` in the udp transport outcomes of
each family it would have made a leg in, and in `h3=` (and `ipv6_h3=`), never
a success, a silence or a skip.

**Platform guard.** The URL common-mode guard gains an HTTP/3 window
(`provider_url_probe_common_mode.go`): when the latest HTTP/3 legs of 16
networks all went silent with none reaching its site, a run whose only failure
is a silent leg is held back (claim retried without credit), so a prober-side
QUIC fault cannot fail every provider at once. One leg that reaches its site
ends the episode.

**Per-country switch** (owner, 2026-11-11: "an optional field per country that
lets udp probes be disabled for the country, if there is some national firewall
issue"). `qualityprobe.yml` takes an optional `country_settings` map keyed by
ISO 3166-1 alpha-2 code, read in either case and served lower-case;
`<cc>: {udp_probes: false}` turns UDP probes off for exits in that country, and
a country not listed, or an entry without `udp_probes`, keeps them on. The
parse (`parseProviderEgressCountrySettings`) refuses a key that is no
two-letter code, or that repeats a country, alone (`country_invalid`, logged and
counted with the other catalog refusals); the rest of the file stands. A
well-formed code ISO 3166-1 does not assign (`zz`) matches no provider and is
ignored; a value that is not a boolean is a catalog error like any other. Only the
countries that turn UDP off are served, in the pool's `country_settings` and its
version, so a catalog without any keeps its pool version. The prober's health
hook looks the country up for the place the due claim gives the provider
(`network_client_location_reliability`'s country, the one the place judgement
reads), and the load's leg plan then makes no HTTP/3 leg in any family for an
h3 URL (`url_family.go`, from the attempt loop in `retry.go`): the load is
judged on its HTTPS legs alone, as a URL without h3 is,
and its evidence keeps the destination's `h3` and says
`udp_probes_disabled: true`, so UDP is recorded as not measured, never a
failure or a pass. With no leg, the outcome adds no place evidence and gets no
verdict (`JudgeProviderEgressH3` returns it at its first check), so those exits
never count toward the three-network rule, and it never enters the HTTP/3
common-mode window, so it neither trips nor ends an episode. The HTTPS leg
counts everywhere an HTTPS leg does. Config sets it for cn, ir, ru and tm
(factury `reports/National QUIC blocking by country.md`); exits in occupied
Ukraine that geolocate as ru are covered, and ua stays on.

**No global switch.** The requirement applies to every URL whose entry says
`h3: true` in every country that keeps UDP probes on; timing is the release of
the taskworker build and of the config.

## Deploy chain

1. `db migrate` on Main for the new table (`providerEgressH3PlaceMigration`,
   appended last: 957 with origin/main 6511ccf8b merged in; it creates one
   empty table). Main is at 954 on 2026-11-11, so the migrate also applies
   main's 955 (crypto scan chain) and 956 (per-cycle Pro grants). Every service
   built from main after this lands waits in readiness until Main has the full
   head (`MinimumRuntimeMigrationVersion`).
2. The monitor watcher's build, before the taskworker: its tailer pattern
   (`monitor/tailer.go`) must know the record's `h3=` field and `h3` failure
   stage, or every probe record of an h3 URL that names a failure counts toward
   the novel class.
3. The taskworker build: it runs the URL lane and, in process, the ingest that
   judges and stores. This is the switch.
4. api and alt for the standalone prober's HTTP ingest (old api/alt refuse an
   outcome carrying `h3` fields: the operator ingest rejects unknown JSON
   fields; non-h3 outcomes are unchanged).
5. The config release with `h3: true` (b2e0b76). Old binaries ignore the key
   (non-strict YAML; the prober's pool decode ignores unknown fields), so config
   and code can ship in either order; the requirement starts when both run.
   The same holds for `country_settings`: the deployed parse (yaml.v3
   `Unmarshal`, no `KnownFields`) ignores it, so it may reach config main
   before or after this code. A standalone prober's outcome that carries
   `udp_probes_disabled` needs api and alt from this build (step 4).
6. The Grafana panels (`bringyourctl grafana load-defaults --dashboards_only`).

## Impact estimate (Main, read-only, 2026-11-11)

- **Exposure.** Config b2e0b76 marks 64 of the 121 served destinations h3, and
  no country lists are served, so about 53% of URL turns draw an h3 URL. In the
  8 hours before about 11:30Z, 116,284 providers had URL outcomes (19.1 runs each on
  average) and 43,099 of them met the Quality ratio (at least 4/5).
- **What failing costs a provider.** A provider that drops UDP where its place
  carries QUIC fails about 53% of its turns, so it falls below the Quality and
  Speed ratio and ranks in the Online fallback (index about 4); it is not
  removed: `no_success` needs every general run to fail (about 0.58^19 for a
  provider passing 90% over HTTPS). Zero-carry needs contracts that carry
  nothing, which a UDP-less provider's do not. Every one of the 43,099
  Quality-ratio providers that drops UDP leaves the native pools; with an
  unmeasured UDP-less share u, that is u x 43,099 providers (2,150 at 5%).
- **No stored measurement sends QUIC through providers**, so u is unknown. The
  one UDP signal is the URL probe's plain UDP/53 DNS for providers in cn, ru,
  ir, tr, kz and tm (connect `RegionalDnsResolverSettings`). Over 6 hours, the
  share of providers whose DNS never answered in at least 3 runs was ru 83%
  (1,504 providers), cn 70% (153), tr 75% (48), kz 94% (16), ir 17% (6),
  against 6.7% of 111,252 elsewhere, where DNS is DoH over TCP. It is not a UDP
  measure: the failures sit in particular builds (`v2026.11.1-...-meso` 736 of
  821, `2026.11.9-...-fix.35.8` 353 of 445, `2026.10.22-...-fix.34.3` 139 of
  151) while others in the same countries answer (`1.0.4-106` 34 of 34,
  `2026.8.22` 11 of 11). Russian providers' URL runs have failed at DNS on
  about 92% of runs every day since at least November 6, a separate
  pre-existing fault worth its own look. Those places would be judged
  `place` for HTTP/3 in any case unless their networks reach the URLs over
  QUIC.
- **Turn cost.** A passing leg adds one QUIC handshake and request through the
  warm tunnel; a silent leg ends at the 3-second handshake bound. The turn
  reserve grows 10 s (220 s to 230 s).

## Measure before it counts

To measure before the requirement counts, without a code switch, release the
config in two steps:

1. Mark a handful of the 80 URLs (say 5 of the 121 destinations, about 4% of
   turns) for 48 hours. Each provider draws four or five HTTP/3 legs in that
   time; the scoring effect is within the Quality ratio's slack.
2. Read the transport panel and, from the history, the per-country silent
   share and the verdicts:

   ```sql
   SELECT url_probe_evidence->'h3'->>'udp' AS udp,
          url_probe_evidence->'h3'->>'verdict' AS verdict, count(*)
   FROM provider_egress_health_history
   WHERE measured_at > (now() AT TIME ZONE 'UTC') - interval '24 hours'
     AND url_probe AND url_probe_evidence ? 'h3'
   GROUP BY 1, 2;
   ```

3. Then mark the rest.
