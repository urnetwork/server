# Explicit legacy prelaunch closure

This is an inert procedure and source contract, not an activation command. It
requires separate operator approval for one affected executor and exact attempt.
It does not authorize a reboot, a candidate restart, a retry, a new evaluation
cycle, a clock extension, or changes on another executor.

The original attempt must remain `accepted`, `launch_attempted=true`,
`execution_started=false`, and `recovery_active=true`. Its original signed
manifest, root cleanup plan, persisted job clock, physical slot and exact state
snapshot are content-bound in a private root-owned authorization. Ordinary
`RecoverActive` continues rejecting a missing evaluator unit.

## Prepare and review before any mutation

1. Inventory the complete native state, boot identity, original absolute
   deadline, original role/config pins, and all launch-capable generations.
   Do not print keys, requests, hidden seeds, patches or evaluator output.
2. Preserve the exact historical forced-command wrapper and canonical recovery
   service bytes in new immutable root-protected archive paths. The authorization
   pins both original identities and archive bytes. The inert wrapper must
   replace the **original wrapper pathname in place**; changing only sshd's
   current configuration cannot fence an already accepted connection's cached
   command. The historical wrapper template is checked, not guessed.
3. Inventory PID1's complete fixed managed-control namespace and the protected
   managed-control registry. Every historical executable/config pair goes in
   `prior_control_roles`, including generations whose registry receipt is gone.
   The native census matches actual executables and argv paths, not just the
   newest agent pathname. Unknown generations refuse closure.
4. Review the new recovery-only executable, exact authorization, rendered
   service, owner-denial drop-in and evaluator mask. New files must have exclusive
   creation, protected parents and immutable public digests. Do not copy signing
   keys or change the original execution configuration.

The authorization schema is `LegacyPrelaunchAuthorization` in
`competitionagent/legacy_prelaunch_recovery.go`. It pins the original config,
state/manifest/cleanup-plan/clock digests, approval digest, host/run, boot UUID,
historical wrapper/archive, fixed SSH route, new recovery-only agent/service,
owner start denial, and historical control roles. It contains no proof Boolean.
The file must be a private root-owned single-link `0400` regular file.

## Approved affected-host launch fence

1. Replace only the original forced-command wrapper with
   `RenderLegacyPrelaunchIngressFence` bytes. Retain its old exact archive.
   Verify effective sshd routing for the fixed control account still selects
   that pathname and the same protected authorized-keys file.
2. Positively close/join the control-account SSH connection and monitor
   generations and every old native launcher or pending systemd-run issuer.
   Uncertain/pre-auth SSH children refuse closure. Authenticated operator
   sessions for other accounts need not be interrupted. Do not stop the global
   SSH listener, another executor, the main coordinator, or unrelated services.
3. For an unrecorded historical failed control unit, first retain its complete
   manager/native audit: exact transient fragment, executable/config pins,
   invocation, no queued job, no main/control PID, native empty cgroup, and absent
   canonical admission. Only then may a separately reviewed operation reset
   failure for that **exact unit**. Require independently observed PID1 retirement
   and native cgroup absence afterward. No global reset, fabricated registry
   plan, ignored unknown unit, direct transient-file deletion, or metadata-only
   inference is permitted. Keep its executable/config coverage in the permit.
4. Install the exact owner-denial drop-in generated by
   `RenderLegacyPrelaunchOwnerDenial`. It combines `RefuseManualStart=yes` with
   `ConditionPathExists=!<authorization-path>`; the protected authorization stays
   present. A manual-start prohibition alone does not deny dependency activation.
   Require PID1's exact loaded drop-in path, no daemon-reload requirement and a
   retained original transient owner fragment.
5. Install a permanent exact-run evaluator mask and require PID1 to report the
   exact mask as loaded. This is a **new launch-denial tombstone**, never evidence
   that the original evaluator existed or stopped. A normal mask's success alone
   cannot override a higher-priority existing transient fragment.

Before activation, qualify the mask/drop-in and late-start behavior using only
owned inert native services: direct starts, transient starts and dependency
starts must not execute their payload after closure. Preserve receipts and
remove only those owned synthetic fixtures. Synthetic unit tests do not replace
this native manager-semantics qualification.

## Recovery-only activation and proof

The approved service uses the same independently bounded canonical recovery
unit, rendered by `RenderLegacyPrelaunchRecoveryService`, with the new immutable
agent and `--config <authorization> --close-legacy-prelaunch`. It remains outside
ordinary management's failure domain. No alternate root, supplied PID, generic
manager command, signing key, worker role or execution fallback exists.

Only the new permit-specific loader may use the archived exact historical
recovery service pin as its recovery-only cleanup view. Ordinary config loading
is unchanged. The new helper proves its actual PID1 invocation and native
independent placement before touching custody.

It then authenticates the original attempt and clock, commits a resumable
starting receipt, withdraws every authenticated managed-control admission, and
stops/joins that finite manager inventory. The native proof checks effective
in-place SSH fencing, original boot, all known old executable/config paths,
control-user and uncertain SSH generations, exact owner/evaluator start denials,
no queued jobs or PIDs, and independently empty native cgroups.

Only this positive launch-surface proof precedes the **unchanged full**
`Agent.Cleanup` chain: exact complete run-parent freeze/kill/join, independent
Docker owner/journal quiescence with zero unknown mutations, authenticated scoped
resource cleanup, frozen-empty readback, durable current-run resource-reap
receipt, parent retirement and mount verification. No missing parent is treated
as an old reap before that receipt exists.

The launch-surface and recovery-placement proofs are repeated after cleanup.
The authorization, original snapshot, physical slot, clock and all provenance
bindings are rechecked. A distinct immutable `legacy-prelaunch-closed.json`
receipt precedes the final failed state and clearing `recovery_active`. Failure,
cancellation, changed generations or missing authority retain custody. Never
delete or rewrite a starting/closure receipt to make a new permit fit.

The result is an honest prelaunch infrastructure failure, not evaluator output,
a score, a qualification, or a historical causal diagnosis. `launch_attempted`
and `execution_started` remain unchanged, as do the original deadline and all
frozen images, seeds, baseline and source identities.

The existing failure archive requires a compatibility file named
`worker.stderr.log`, although a genuine prelaunch attempt has no evaluator
stderr. Initial absence is positively checked and recorded before any cleanup.
The recovery role writes a structured **operator recovery diagnostic**, not
evaluator output, under that compatibility name. It states
`provenance=operator_legacy_prelaunch_recovery`, `evaluator_started=false`, and
`original_evaluator_stderr_exists=false`, and embeds the complete non-secret
closure receipt. Thus the current ordinary failure archive retains the proof
bytes with its normal SHA/version/retention verification. No blank fake stderr,
worker result, score, success claim or original-file overwrite is permitted.
Crash resumption accepts only the byte-identical diagnostic for the same retained
receipt and authorization; any different existing bytes retain custody.

## Handoff and forbidden shortcuts

After the new recovery service has joined, restore the exact historical
canonical recovery service before reopening ordinary ingress. Keep old-run
launch-denial tombstones in place. Recheck native host/runtime health and retain
all operator/manager/cleanup receipts. A central controller failure commit still
requires its ordinary authenticated transport and immutable artifact retention.

The existing controller classifies failed native terminal responses as
non-retriable infrastructure failures. Any later retry requires separate genuine
authority and the remaining **original** absolute budget; closure does not grant
that authority or start a new clock.

Future Docker-owner entry failures can retain
`competition-docker-owner-failure/v1` root metadata containing only a finite stage
and cause digest. The first record is preserved; it contains no raw error or
private material and cannot reconstruct any older discarded error. Failures
before the native entrypoint ran still require genuine PID1 evidence.
