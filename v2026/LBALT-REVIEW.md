# Review of the lb_alt proposal

**Recommendation.** Proceed with the front implementation and the nginx comparison harness. Hold the first public cutover until a client can use both whodis ports and keep an established session through a deploy or rollback. Before moving `alt.*`, prove that rolling an interface back to nginx preserves API-over-QUIC access for clients that cached its edge address. Terminating connect sessions directly removes a copy from their data path, and forwarding API requests to existing block ports preserves independent API deploys. The edge-4 experiment establishes that HMARK can select a bucket. It leaves the end-to-end return path unverified. [Proposal, decisions and measurements](LBALT.md)

## Before the first public cutover

### 1. Publish UDP 4053 explicitly, on the host and at the router

D3 and D14 promise both public 53 and public 4053. Today's two deployments have different port contracts. On a normal edge, warpctl deliberately makes the target of `53 → 4053` private. The VyOS generator also omits 4053 from the WAN rules. On an alt host, the external-port helper publishes both the alias and its target. Shipped clients try 4053 as a second whodis port. A working socket and a successful UDP 53 probe can therefore coexist with a broken client fallback. [Edge and alt port maps](../warp/warpctl/run.go#L3203) · [Router rules](../warp/warpctl/vyos.go#L315) · [Client port selection](../connect/net_alt.go#L160)

Give lb_alt an explicit public port list that both generators consume. Test TCP 80/443 and UDP 443/53/4053 through the generated host and router rules. Run a whodis exchange on **both 53 and 4053** and verify the public reply address and port. Keep the legacy forward-target privacy test for nginx interfaces. Derive the family matrix from the inventory. Main has ten public IPv4 addresses and eight public IPv6 addresses. Edge-0 `eno3np2` and edge-1 `eno4` have IPv4 only. Choose one of the low-weight dual-stack interfaces for the first switch. [Existing port-contract tests](../warp/warpctl/run_test.go#L1531) · [Main interface inventory](../vault/main/services.yml#L349)

### 2. Specify how nginx and connect hand over an interface

D1 moves new TCP and UDP flows together. Existing conntrack entries still deliver packets to the original process. After the first switch, nginx on a neighboring interface also continues to create **new** plaintext H1 and PROXY-v2 UDP traffic for the same five connect blocks. Removing the private listeners when the first interface drains would break that neighbor and a subsequent rollback. The private HTTP port also serves the candidate readiness poll and targeted block routes. The exchange has its own internal sockets. [Legacy listeners](connect/transport.go#L2283) · [Candidate status poll](../warp/warpctl/run.go#L2314) · [Exchange listener](connect/resident.go#L1519)

Start compatible blocks on generation-specific ports while nginx still owns ingress. Preserve the trusted services-bridge listeners for every nginx dependency and the private status and exchange paths for their full lifetime. Bind the public front only to its declared interface addresses. Disable PROXY decoding on public UDP and derive public HTTP ingress headers from the accepted peer. Confirm the router and host rules keep client traffic off trusted ports. Probe the new owner before switching new flows, keep the old owner alive through drain, and apply the same ordering in reverse.

Test a host with one interface in each mode. Hold an established connection through each direction of the switch while fresh sessions succeed on both interfaces. Exercise D2 with an absent interface override, explicit `true` under a disabled service default, and explicit `false` under an enabled default. That last case is the rollback switch. Keep routing-only edge interfaces in DNS and mover inventory. The existing `transparent` flag excludes a host interface from the weighted lb set. [Routing-only worker](../warp/warpctl/run.go#L235) · [DNS membership](../warp/warpctl/dns.go#L192) · [Edge inventory](services_lb_inventory.go#L73)

### 3. Make readiness and DNAT refer to the same generation

D10–D13 introduce an interface reconciler and five independently deploying block owners. The current port allocator checks one bridge address per family and records occupancy by port number. UDP conntrack cleanup uses that occupancy and the reply address of the selected bridge. With several bridges and `SO_REUSEPORT`, a successful bind alone cannot establish exclusive ownership of a generation. A stale port or premature cleanup can send a repeat dial to a dead target or interrupt a live drain. [Port discovery](../warp/warpctl/run.go#L1699) · [Conntrack cleanup](../warp/warpctl/run.go#L1906)

Have warpctl probe the candidate's private allocated port for its generation, route-file version or digest, and full expected listener set. Require an explicitly ready generation. The ordinary Warp status parser accepts `draining` as informational. Count all four sockets for each required address, protocol and port. Alt currently records a single readiness boolean per transport and address, so four sockets on the same endpoint collapse to one entry. Specify what happens when one exits after promotion. Rebuilding a UDP reuseport group can move existing flows between independent QUIC transports. [Warp status contract](router/warp_handlers.go#L80) · [Alt listener registration](alt/alt.go#L207) · [Connect listener supervision](connect/transport.go#L1230)

Build complete replacement chains before switching the entry jump. Specify who writes each chain, a stable hash seed and range ordering, and how a restarted worker recovers from an interruption between families. Keep the last working targets until the replacement is complete. Reassign only the missing ranges to ready blocks according to their weights. If every target is down, fail interface health. Exercise a block promotion concurrent with an lb reconcile, block loss and return, stale UDP tuples, and an interrupted rollback in a two-interface Linux network namespace. Check both directions of traffic, the original public source on replies, and the routing marks on unrelated traffic. M7 exercised loopback traffic and one IPv6 source. [Deploy cutover](../warp/warpctl/run.go#L1457) · [M7 test scope](../xops/main/ansible/files/lbalt-hmark/lbalt-hmark-test.py#L5)

### 4. Start the HTTP/3 drain while its transport can still send

D12's GOAWAY requirement intersects with a production failure. Connect currently calls `exchange.Drain()` and then cancels the serving context. Alt's listener teardown closes its QUIC transport. Alt explicitly uses a bounded HTTP/3 close because invoking graceful shutdown while that transport was being destroyed produced hundreds of thousands of GOAWAY writers. Porting the dispatch and adding a late `Shutdown` would bring that shutdown ordering back to the edge. [Connect shutdown](connect/run.go#L205) · [Alt shutdown rationale](alt/alt.go#L511) · [Pinned HTTP/3 accept loop](../quic-go/http3/server.go#L502)

After the DNAT switch, begin draining the old HTTP front while its transports are live. Stop admitting new HTTP work, close idle H1, initiate H2/H3 GOAWAY once per connection, and let accepted requests finish alongside the resident drain. Track hijacked H1 connections and both sides of forwarded websockets through the deadline. Give forced transport close a bounded completion path. Carry over alt's shutdown regression tests and add a case with an in-flight H3 response, a new stream during drain and an established websocket. Verify the old response completes, a fresh dial reaches the new generation, and the deadline releases the old sockets. [Existing shutdown tests](alt/alt_close_test.go#L181)

### 5. Specify request routing after TLS and test the actual connect carriers

D9 describes the default certificate and routes together. On TCP, nginx can select a certificate using SNI and then select an HTTP virtual host using the request line or `Host`. H2 supplies authority per stream. Also, nginx forwards its normalized `$host`, while a Go proxy copying `Request.Host` can retain a port. Alt's wildcard matcher accepts one label. An nginx wildcard server name can match several. Use the pinned nginx image to settle HTTP routing and default-host behavior. For H3, constrain each forwarded request's authority to the API names admitted by D3. Include missing SNI with a known Host, differing known SNI and authority, two authorities on one H2 connection, and exact versus wildcard names. Assert the selected certificate, upstream, forwarded Host and access to status routes. [Generated proxy headers](../warp/warpctl/config.go#L2504) · [Alt host matcher](alt/hosts.go#L108) · [nginx virtual server selection](https://nginx.org/en/docs/http/server_names.html#virtual_server_selection)

Connect's native H1 path also supports the `urnetwork-framer/1` upgrade (H1+). On UDP, connect uses raw QUIC and can offer no ALPN, while API requests use HTTP/3 with `h3`. The QUIC config alt inherits sets `Allow0RTT: true`. Waiting for handshake completion before dispatch and disabling early data at negotiation are separate controls. Apply D9 explicitly to the public QUIC config and verify a resumed session reports `Used0RTT == false`. Preserve the shared handshake admission limit across all sockets. Exercise WebSocket, H1+, raw QUIC and API H3 with real client code, including authentication, a bidirectional exchange, whodis on both ports, and the existing refusal behavior. [H1+ selection](connect/transport.go#L1554) · [QUIC defaults](connect/transport.go#L847) · [Alt ALPN selection](alt/alt.go#L356) · [Admission tests](alt/alt_admission_test.go#L183)

The release record identifies the fix behind §4.4's rollback floor of build 1088438700 as connect `6203a4e8`. A failed carrier recovers independently. Carry that requirement into D13 and adapt the existing listener-loss test to the new front. Verify that sibling carriers keep serving and that readiness reflects the missing socket until it recovers. [Release record](../connect/EXTENDER-ACTIVATION.md#L390) · [UDP listener recovery test](../connect/extender/extender_carrier_resilience_test.go#L409)

### 6. Bound retries, buffering and limits at their actual scopes

- **Retries.** D7 correctly retains one retry on transport error, timeout or upstream 503. The explanation of API drain needs correction. SIGTERM marks status as draining and closes the serving listener. A stale pooled connection or refused dial is the ordinary retry case. An upstream application 502 previously caused a password reset to execute twice when retried. Specify at most two upstream attempts on distinct eligible blocks, before a response is committed to the client. A block-specific status request must report the named block's result. Streamed bodies become ineligible for retry once forwarding begins. Exercise a buffered POST across a drain, a 503 with byte-identical replay, application 500/502/504, and a partial response. Count attempts at a recording upstream, including any automatic retry by Go's transport. A timeout after a POST reached the first block still permits duplicate execution under D7. [API shutdown](api/run.go#L140) · [Existing retry regression](../warp/warpctl/config_retry_test.go#L8) · [nginx retry semantics](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_next_upstream) · [Go HTTP transport](https://pkg.go.dev/net/http#Transport)
- **Body storage.** D19 bounds resident body prefixes. Its 4,096 full 64 KiB prefixes can accompany **63.75 GiB of temporary data per process** at the 16 MiB request cap. Give the spill directory a byte and file-count limit sized against the host filesystem and overlapping generations. Define reservations for unknown-length bodies before the first read, enforce 413 as the body crosses 16 MiB, and distinguish a local capacity 503 from an upstream 503 eligible for retry. Test 64 KiB and 16 MiB boundaries, cancellation during spill or replay, and failed writes with a small injected quota. Verify every exit releases bytes, descriptors and files. [D7 and D19](LBALT.md#f-found-while-checking-the-measurements)
- **Limit identity.** D8's source hash pins an address to one block, but each block serves two or three interfaces. One process-wide address bucket would make independent nginx interfaces consume each other's quota. Key the shared request and concurrency zones by ingress interface and normalized client IP. Scope route buckets to the service and matched route within that interface. Preserve exact lb status exemptions, excluded subnets and per-stream accounting on H2/H3. Hold upgrade concurrency until the tunnel closes. Test one source across two interfaces, two services, two reuseport sockets and a deploy overlap. State the temporary allowance when a draining generation still owns sessions. [Alt limiter state](alt/rate_limit.go#L157) · [nginx zone generation](../warp/warpctl/config.go#L1666)

## Before moving alt DNS

D14 and D18 need a common rollback procedure. A restored nginx interface can answer its TCP 80 health check while sending UDP to the legacy connect-only handler. A client with the edge address cached would lose access to the API over both plain QUIC and whodis there. DNS withdrawal helps only after the client obtains another address. Also, the generator emits host-pinned alt records, rejects conflicting definitions of the same name, and skips `dns_aliases` on exposed services. [DNS ownership and collision check](../warp/warpctl/dns.go#L248) · [Exposed and host-pinned name generation](../warp/warpctl/dns.go#L349)

Give each alt record one DNS owner during the handover, while the old service can still answer cached proxy addresses. Compare the complete before-and-after record sets, including the implicit `<env>-alt` names, bare aliases, A-only `-v4`, AAAA-only `-v6`, weights and health membership. Exclude DNS-only names from TLS and HTTP route generation. Track successful extender activations by carrier and family alongside the decline in old-host traffic. Clients that lose reachability when both names share edge addresses also disappear from the old counters. [Client name derivation](../connect/net_alt.go#L19) · [D14 and its address-diversity tradeoff](LBALT.md#d-alt-removal)

Before retiring alt, rehearse rollback with a client pinned to the *old* proxy address and one pinned to the *new* edge address. One way to support immediate interface rollback is a PROXY-aware private backend that still dispatches API H3 behind nginx, plus a published UDP 4053 path on that fallback. Keep an operable alt deployment and router rules through the post-DNS soak, and retain a tested nginx image with usable certificates for the rollback window. [Current nginx UDP forwarding](../warp/warpctl/config.go#L2818)

## Evidence for promotion

### HTTP behavior and upstream choice

Generate the route file and nginx config from the same fixture. Use recording upstreams for requests with side effects. Compare the URI and query, bytes in both directions, headers and attempt count. Cover hidden per-block routes, redirects, CORS preflight and errors, `Vary: Origin`, CSP-dependent frame options and streaming. Preserve the TCP service-name status denial and alt's API H3 `/status` 404. Apply ingress rewriting once, including removal of client-supplied `Early-Data`, which the shared header helper currently leaves in place. Exercise a progressing upload beyond the idle timeout and a stalled one on the artifact route's 60 s override. [nginx route generation](../warp/warpctl/config.go#L2381) · [Alt public API](alt/ingress.go#L34) · [Ingress helper](router/ingress.go#L93) · [Proxy timeout semantics](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_read_timeout)

Hold requests open to check weighted `least_conn` under known load. For the configured stateful service, compare the selected backend with nginx's weighted Ketama ring on fixed IPv4 and IPv6 client addresses. A different consistent hash can be internally stable while remapping clients during a mixed rollout. [Upstream generation](../warp/warpctl/config.go#L1820) · [nginx consistent hashing](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#hash)

### Certificates and config revisions

Load an immutable, schema-versioned route file and complete matching certificate/key pairs before advertising readiness. Retain upstream targets referenced by older route files until the last block using them has drained. Validate SAN coverage for aliases, parent fallback and wildcard names. Report the config revision and earliest certificate expiry on private status. The lb image contains the generated config with versioned certificate paths. The keys come from a read-only vault mount. Rehearse rotation and rollback before the proposal's 2027-01-15 expiry. For D6c, use a long-lived TLS configuration for the intended ticket scope and verify resumption across sockets within one block. Go's automatic ticket keys belong to the configuration used by the server. [Key selection](../warp/warpctl/config.go#L849) · [lb image inputs](../warp/lb/Dockerfile#L104) · [Vault mount](../warp/warpctl/run.go#L2108) · [Go TLS configuration](https://pkg.go.dev/crypto/tls#Config)

### Public health and performance

Validate a 200 and the expected status JSON on port 80. Route 53 also accepts 3xx, so an accidental HTTPS redirect can look healthy. Probe individual blocks as well as the public address, since one probe source follows one hash bucket. The monitor currently rejects a target with service `connect` and front `api` in both validation and transport code, and its probe ends at the handshake. Update both checks and exercise an API request such as `/hello` over the new path. [Monitor inventory](monitor/public_udp.go#L146) · [Monitor transport](monitor/public_udp_transport.go#L174) · [Route 53 health criteria](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/dns-failover-determining-health-of-endpoints.html)

D16 assigns beta one of 100 source-address buckets. **The first interface switch sends new traffic to all five blocks.** Qualify beta with pinned test traffic before that switch, then compare the whole interface with an nginx control over the same interval. Measure actual traffic share and per-block skew, especially behind large NATs. M4 reports socket drops and UDP pseudo-sessions. It leaves application latency and the exact client mix unmeasured. The referenced performance harness dials a plaintext loopback URL in H1 mode. Pin WebSocket and H1+ separately, add QUIC and whodis cases, and capture an nginx baseline before switching. [Performance harness](connect/connect_perf_test.go#L356) · [M3 and M4 measurements](LBALT.md#71-results-2026-11-18-2020z)

Set numerical promotion and rollback thresholds from those baselines. Track H1/H1+ upgrade success and p99 application RTT, QUIC/whodis success and RTT, forwarded 5xx and retries, CPU, scheduler delay, socket drops and spill usage. Include a reconnect wave with full and resumed handshakes. D15's `cores: 20` sets `GOMAXPROCS` on hosts already measured at 80–88% peak busy. Observe a busy period and a complete deploy, drain and rollback before expanding. [Worker CPU setting](../warp/warpctl/run.go#L2196) · [Host measurements](LBALT.md#71-results-2026-11-18-2020z)
