# Multi-repository instrument bridge — proposal only

**Not approved, frozen, executed or accepted.** The user has been asked whether
to approve this explicit bridge or require a full five-pair restart. Until that
decision, the original campaign remains authoritative and its records must not
be relabeled. Public opening remains October 28, 00:00 UTC.

## Why a new instrument is necessary

The user approved product-file changes across all ten locked repositories.
The old trusted simulator permits a candidate commit only in server. API and
builder changes alone cannot make a dependency patch measurable: the protected
runtime verifier correctly refuses it under its old contract.

The prospective verifier therefore has an explicit image-lock capability,
`candidate_path_base: mono_root_v1`. With that trusted flag, each repository
must remain clean at its frozen commit or exactly one direct candidate commit
above that commit. Unknown flags fail closed. Omission preserves the old
server-only contract. The capability is not submission-controlled and does not
replace API patch screening, exact applied-tree verification, containment,
honesty review or the independently protected `server/connect/sim-latency/**`.

## Proposed acceptance sequence

1. Finish and preserve every declared original Stage A outcome. Obtain an
   accepted native analysis of the complete five-pair sample and publish its
   exact inputs, algorithm and selected practical margin. It remains evidence
   for server `c1f9dda603d6279666fca5d92b99c5663306c5f7` and evaluator image
   `sha256:002c39040ce23dee27b171c7e657f749c6a6d05b1e9b97d90ac87336470dbaf3`.
2. Freeze a separate minimal evaluated-source revision for the source-identity
   capability. Audit its diff against that exact source: no workload, critical
   product path, score aggregation, gate, significance, resource, timer or
   replicate changes. Preserve the unchanged nine other repository commits.
   Moving main control-program changes are not silently part of this source.
3. Build and qualify the new immutable source/image/scripts/validator with
   actual Go 1.27.3. Retain exact source/binary/image identities, deterministic
   old-contract refusal and new-contract acceptance tests, scorer/gate boundary
   tests, containment, cleanup and source-graph proofs. Demonstrate unchanged
   scoring source/semantics without rewriting original driver records to make
   their old identities look like the new instrument.
4. Before observing new full-window results, freeze one fresh no-op R9/R9
   invocation on the revised release with its own round/job identities,
   workload/request/patch/build/policy pins and original three-hour deadline.
   Preserve both arms, all gates, variance, significance, integrity, resource
   and cleanup evidence. No old control sample is reused as this new baseline.
5. Under the already selected margin, require complete placeable results,
   all six gates, exact cleanup, the original time bound and no no-op takeover.
   Report any statistically significant no-op outcome even when the practical
   margin prevents takeover. An adverse result stops the bridge for diagnosis;
   it does not authorize a replacement pair, a larger margin or a clock reset.
6. If accepted, publish a compatibility receipt explicitly separating the
   prior-instrument noise estimate from the revised-instrument live proof.
   This is not five fresh same-seed pairs on the revised binary and must never
   be described as such. The held-out tool must bind that approved relationship
   explicitly; its current exact-release pins cannot simply be overwritten.
7. Precommit the full independent-seed/reference screen on the revised release
   before its first result. All five seeds get fresh revised-release controls;
   no original Stage A or bridge control is reused. Keep the existing sampling,
   randomized reference order, four-of-five ordering, no-op, integrity and
   deadline rules. Qualification and public activation remain separate gates.

## Limits and alternative

A source-diff audit and one successful no-op pair do not statistically prove
equivalence of latency distributions. The proposal retains the older noise
estimate on a declared engineering-compatibility assumption; user approval is
required. The extra pair is not a substitute for the independent-seed screen,
nor permission to weaken measurement integrity or honesty review.

The alternative is a new predeclared five-pair Stage A campaign on the revised
release, followed by its own frozen margin and the independent-seed screen.
That adds approximately fifteen hours of serial measurement versus the old
sample. Neither option permits changing the announced opening or claiming a
gate passed without its actual evidence.
